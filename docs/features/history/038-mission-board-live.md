# 038 · Mission Board Live — DONE

## What it added

Replaced the hardcoded `MissionBoardScene` placeholder with a live, TTL-cached mission list generated by `MissionGenerator`. Added `MissionDetailScene` showing full mission info, cargo availability check, and ACCEPT/BACK navigation; accepted missions are spliced from the cache so they don't reappear until the TTL expires.

## Key files

- `src/game/scenes/mission-board-scene.ts` — rewritten to accept `getMissions` and `onMissionSelected` callbacks; renders type icons, rewards, giver sub-lines; empty state message
- `src/game/scenes/mission-detail-scene.ts` — new scene extending `BaseMenuScene`; renders full mission details with colour-coded cargo check; computes `giveItemNow` and passes to `onAccept`
- `src/game/scenes/base-menu-scene.ts` — patched to render `details` sub-lines for icon items
- `src/game/game.ts` — `missionBoardCache`, `getOrCreateMissionBoard()`, `goToMissionDetail()`, `onMissionAccepted()`
- `src/game/scenes/mission-board-scene.test.ts` — full rewrite (26 tests)
- `src/game/scenes/mission-detail-scene.test.ts` — new (24 tests)

## Architectural decisions embedded

- `missionBoardCache` follows the same `Map<destinationId, { data; generatedAt }>` pattern as `traderStockCache`, with a 15-minute TTL vs 2 minutes for trader stock
- `giveItemNow` is computed in `MissionDetailScene` from `spec.pickupDestinationId === spec.issuingDestinationId` (always true for generated delivery missions), not passed in from `Game`
- ACCEPT nav button is conditionally included in `navOptions` (absent when `canAcceptMission` returns `{ ok: false }`), satisfying the "disabled and visually dim" requirement within the existing chrome system
